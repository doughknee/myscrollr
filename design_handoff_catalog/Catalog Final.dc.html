Behavior rules

  • Hub is the default landing. Directory is a sub-state of the same route (?kind=sports, ?q=…) so Back and deep links work.
  • Typing anywhere switches to directory results grouped by kind; clearing the field returns to the last kind, not the hub.
  • Picking a kind in the rail clears the query (same rule as today's segmented tabs).
  • + adds in place; ✓ removes on click with a toast undo. Row body still opens the existing slide-over panel.
  • Zero matches → request card + closest group. Request is one click, counted server-side, and subscribes the user to a “shipped” notification.
  • At slot cap, + opens the panel with the upgrade path (unchanged); the cap reads on the sidebar chip, the rail, and the hub line.

Growth rules

  • A new kind is a new hub tile and a new rail item — server-only, no client release (same contract as today).
  • Kinds with more than ~8 widgets must carry groups (Soccer, Motorsport, Business, Dev…). Under that, the group header is hidden.
  • Group pills in the directory header become jump anchors once a kind passes ~24 rows; add an A–Z sort past ~60.
  • Hub tiles show 5 logos + “+n”; the “n new” tag uses added_at within 30 days.
  • “New this month” caps at 4; overflow goes to a “See all new” link into the directory sorted by date.
  • The rail scrolls independently; at 12+ kinds it still fits without collapsing.

Catalog schema additions

  • group — sub-shelf label inside a category (“Soccer”). Optional; missing → ungrouped.
  • keywords[] — search aliases (“bitcoin btc eth”). Included in the match haystack with name, description, group, category.
  • added_at — drives “new” tags and the New this month strip.
  • POST /catalog/requests — { query, user } ; returns count. Powers the miss card and the roadmap.
  • Category order stays server-defined; the hub grid is 4-across so 7–8 kinds fill two rows with the “Something else?” tile last.
