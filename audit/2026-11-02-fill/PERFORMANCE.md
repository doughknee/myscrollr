# Fill this display — performance audit

Calibration: this is an always-on wall display. Sustained memory, idle CPU, repeatable page motion, and cleanup matter more than a cold launch. Baseline audited: PR #529 commit `75a74c4b`; source references below refer to that commit. Read-only inspection; scripts and evidence are confined to this audit folder. P0 blocks review, P1 must be fixed before release, P2 is backlog. No P0/P1 performance defect demonstrated; hardware release gates remain.

## Findings

### PERF-1 — P2, fixed and verified in root worktree: the clock invalidates the full grid and bypasses cell memoization

`desktop/src/hooks/useWidgetTickerData.ts:517-520` builds a new widget-data object every second. Its caller is `desktop/src/App.tsx:755`; the state update renders App and PagedBar. `desktop/src/components/pages/PagedBar.tsx:378-409` is an unmemoized Cell adapter and creates fresh onClick functions for GameCell, NewsCell, QuoteCell, and the other memoized cells. Unchanged quotes therefore re-render on an unrelated clock tick; Fill expands the number of simultaneous cells.

Evidence: `results/performance/profiles.json`, generated by `profiles.mjs`, uses React's development profiler root timing, a 1920×1080 `fixture=googl&pages=1&fill=grid` shim, no live simulation, development command bus stubbed in-browser to avoid cross-tab polling contention, 10s warm-up followed by 20s sampling. With `utils=clock`: 24 commits and 203.8ms total inclusive root render time. With `utils=`: 4 commits and 26.4ms. The page continues its normal dwell/turns in both runs. These are development-build measurements, not production CPU guarantees; StrictMode and concurrent local work affect absolute cost. The comparative excess is concrete. Raw component counters in profiles.json are not reliable render counts because reused fiber subtree flags can survive memo bailouts; only commit counts and inclusive root durations are used here. A direct served-module call counter supplies the before/after result below.

Suggested fix: memoize the shared Cell adapter on its stable item/widget/click-handler inputs (including all rendering inputs); isolate utility state below the content tree where practical. Retain original slide/wipe transitions. Root memoized the shared Cell adapter and verified live quote updates in the browser suite. Identical served-module instrumentation (`counter-baseline.json`, `counter-after.json`) measured actual QuoteCell function calls, including StrictMode: 396 before → 36 after (90.9% fewer), with 24 commits in each 20s sample. Inclusive root render duration was 238.2ms → 114.6ms (51.9% lower). Both runs ended with one page and one Fill surface. This is a development comparison, not a production CPU guarantee; root reports all 42 browser cases, 1,035 unit tests and the production build passed.

### PERF-2 — P2: hidden or suspended ticker windows keep utility polling alive

`desktop/src/App.tsx:755` calls useWidgetTickerData outside the `showTicker && !display.suspended` mount gate at line 763. Its clock/timer loops at `desktop/src/hooks/useWidgetTickerData.ts:517-527` continue every 1s; sysmon at lines 569-577 continues IPC every 2s; uptime/GitHub at 583-595 rebuild cached data every minute. The hook's cleanup at 609-620 is correct, but hiding the surface does not unmount the hook or disable these intervals. Fill's disconnected-monitor suspension inherits this cost even though no display is drawn.

Evidence: the same profile harness emits the shim's `toggle-ticker` event, confirms zero `[data-fill-display]` elements, and samples another 20s. With the clock configured, App still commits 20 times (16.3ms measured render time); without utilities, zero commits. Sysmon's invisible polling follows directly from the unconditional hook and enabled-widget predicate; native hidden-window IPC was not exercised. This is a preexisting hidden-ticker issue made relevant by the new suspended state, not a claimed new leak.

Suggested fix: add a visible/active argument to useWidgetTickerData so it clears local display-only polling while hidden/suspended, immediately refreshes on resume, and preserves the independent process-owned SSE/data pipeline.

### PERF-3 — P2, preexisting/outside Fill fix batch: ticker startup includes every utility FeedTab

`desktop/src/widgets/registry.ts:10-12` eagerly imports all six FeedTab modules. The ticker imports this registry at `desktop/src/App.tsx:50` to enumerate context-menu metadata at line 641. Existing production sourcemaps show clock, GitHub, sysmon, timer, uptime, and weather FeedTabs in the shared `style-*.js` chunk, although ticker Fill does not render these screens. `results/performance/bundles.json` records the output and constituent sources. This is inherited architecture, not a Fill regression.

Suggested fix: keep widget metadata/ordering eager in the existing registry and lazy-load FeedTab components only for the main-window feed route. Do not create a parallel widget registry or copied ticker implementation. This is backlog cold-start work; the long-running rendering findings take priority.

## Runtime measurement

The 15-minute real-time soak completed against an isolated detached checkout of 75a74c4b, served only on localhost:5199. Installed Playwright/Edge 156.0.4314.58, 1920×1080, pages fixture, Fill grid, live updates every 4s, clock plus three time zones and demo weather, with one wheel gesture every 30s. GC-controlled snapshots were captured at 1.148s, 301.330s and 901.410s relative to the warmed-up start. `results/performance/soak.json`, `heap-{0m,5m,15m}.heapsnapshot`, screenshots and analysis scripts retain the evidence. No page errors were recorded.

|---|---:|---:|---:|---:|---|
| 0m | 15,297,672 | 463 | 229 | 893 | 2 / 3 |

JS heap rose 2,391,800 bytes overall (+15.6%), predominantly in the first five minutes; the last ten minutes added 415,736 bytes (+2.4%). Page-family changes explain different mounted DOM/fiber counts; there is no accumulating DOM/listener/query population in these checkpoints. This is not proof of indefinite stability or of zero leakage. **UNCERTAIN:** the small residual JS slope cannot be conclusively classified from three development snapshots; a packaged overnight sample on target hardware remains useful.

Dominant retained allocations and ownership (`heaps-summary.json`, `retainer-paths.json`): approximately 12.88MB of native ExternalStringData is backed by Vite/React module-source strings (largest single buffers 2.23MB and 2.01MB). JIT InstructionStream allocation grows 1.72 → 2.77 → 3.00MB. At 5m, 72,524 NetworkResourcesData records consume 20.89MB; at 15m, 72,742 consume 20.95MB. The ownership path is InspectorNetworkAgent → NetworkResourcesData → resource table. Early parallel default-label shim tabs caused development-bus polling contention; those test tabs were closed and subsequent profile/motion harnesses stubbed the dev bus. This is retained inspector traffic, not a demonstrated production application leak. UserTiming retains PerformanceMeasure entries, 19,696 / 2.63MB at 5m and 56,515 / 7.54MB at 15m, another development-profiling cost. Native retained allocations are separate from the GC-controlled JS-used metric above. The first five minutes' aggregate timing is therefore not a clean normal-load benchmark; the separately rerun no-bus motion/profile samples are the timing evidence.

## Timer / subscription cleanup review

The scoped enumeration is retained in `results/performance/timer-inventory.txt`. No accumulating production timer/listener registration was established in the inspected Fill path.

- TickerSurface.tsx:25-53 clears/replaces its 5s idle timer and removes resize/Escape listeners.
- PagedBar.tsx:160-161 removes reduced-motion change; 171-180 stops dwell animation; 372-375 disconnects theme observer; 473-484 disconnects resize observer; 504-507 and 561-569 clear timers; 601-606 clears follower hello; 641-654 removes wheel/key handlers.
- EdgeZone.tsx:260-271 disconnects its resize observer. Continuous pin measurements, ScrollrTicker.tsx:563-586, disconnect their observer, though the dependency-free layout effect repeats measurements/observer setup each render.
- activeHover.ts:15-48 clears its lazily rearmed timer on leave/dispose. This does not by itself send a remote-hover release: resilience owns that independent correctness finding.
- useWidgetTickerData.ts:532-563 returns per-key store unsubscribers; 609-620 clears every configured utility timer and subscriber. Its pending async sysmon completion is not canceled; no retained recurring task demonstrated after unmount.
- App.tsx:98-105, 295-307 and 329-353 unsubscribe store listeners; its contextmenu effect at 546-745 removes the listener. Tauri event handlers use useTauriListener.ts:23-43, which handles async registration resolving after unmount.
- useDashboardCDC.ts:123-126 clears the debounce and 184-189 coalesces repeated invalidations. useTheme.ts:85-104 clears its 350ms transition and system-theme listener. useScoreFlash.ts:36-38 clears its 800ms timeout.
- Intentionally window-lifetime registrations without per-component removal: useCatalog.ts:39-47 binds one online listener behind retryBound; lib/store.ts retains one native onKeyChange listener per fixed store key and removes component callbacks. These are bounded ownership choices, not demonstrated leaks. lib/fonts.ts:18's 1.5s timeout is finite, although it is not canceled after fonts resolve.

## Limits

The soak is development Edge with fixture updates, not packaged WebView2, real CDC traffic, production payload scaling, sleep/wake, physical monitor reconnect, sustained GPU/RSS measurement, macOS/WebKitGTK, or a low-power customer mini-PC. Shared data ownership was inspected, not load-tested against a backend. React profiling covers Fill's App/TickerSurface/PagedBar/EdgeZone/cells and a bounded Continuous rendering sample, not the settings route. Headless rAF cadence measures scheduling; it is not a claim about physically presented frames. Heap snapshots pause the renderer and can appear as artificial long frames in cumulative soak telemetry. The isolated baseline prevents root's fixes/HMR from invalidating the run.
